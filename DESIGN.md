# DESIGN.md — Site Design Specification

The current target design is Bear Blog style, modeled after https://herman.bearblog.dev/. The
wireframe is on Excalidraw (http://127.0.0.1:3000); this file records the specs the implementation
must follow.

## Design Direction

- Bear Blog-style minimalist personal blog: narrow content column, whitespace, plain-text lists, no
  sidebar, no cards.
- The homepage serves as the Archive; there is no separate archive page anymore.
- Use DaisyUI built-in `light` / `dark` themes; do not define custom themes.
- The theme follows the browser `prefers-color-scheme`: `light` is the default and `dark` uses
  `--prefersdark`; there is no theme toggle button and no localStorage theme script.
- System fonts only (`system-ui`, `ui-sans-serif`); no web fonts.
- Main layout is a centered 640px narrow column; on mobile it becomes `100% - 48px` (24px on each
  side).

## Page Structure

### Home `/` (Archive list)

- Header has only the site name on the left and the search icon on the right; no Home, Now,
  Projects, Blog or other links.
- No `Archive` page heading and no search box.
- The page content starts directly with the post list: each row is an italic date + post title
  link, newest first.
- The list shows no description, tags, reading time, thumbnails, or pagination.
- Footer has Copyright on the left and the RSS icon on the right.

### Article `/posts/<slug>/`

- Header is the same as the homepage: site name + search icon.
- Content order: article title → italic date → reading column.
- The body keeps the Typst-generated headings, paragraphs, images, code blocks, blockquotes, and
  MathML.
- The old page-specific bottom links (`rss` / `email` / `hello`) are removed; only the shared
  Footer remains at the bottom.

### 404

- Header is the same as the homepage.
- Content is `404`, a short ASCII error graphic, an error message, and a back-to-home link.
- Footer is the same as the homepage.

## Search Modal (global interaction state, not a standalone page)

- The Heroicons `magnifying-glass` button on the right of the Header opens the modal.
- Uses the DaisyUI dialog modal structure, following the official example:
  https://daisyui.com/components/modal/#dialog-modal-closes-when-clicked-outside
- Target structure:

```html
<button type="button" class="btn btn-ghost btn-square" aria-label="Search"
  onclick="search_modal.showModal()">
  <!-- Heroicons magnifying-glass -->
</button>

<dialog id="search_modal" class="modal modal-bottom sm:modal-middle">
  <div class="modal-box">
    <div id="search"></div>
  </div>
  <form method="dialog" class="modal-backdrop">
    <button>close</button>
  </form>
</dialog>
```

- Clicking the backdrop outside the modal closes it; there is no close button.
- Responsive: `modal modal-bottom sm:modal-middle` — on mobile (<640px) it slides up from the
  bottom (bottom sheet); on desktop (≥sm) it is centered.
- The Lume Pagefind plugin automatically looks for `id="search"` and injects the search input,
  results, count, and highlight; no hand-written JSON index or client search script.
- `#search` must be a `<div>` container, not an `<input>`: PagefindUI mounts its whole UI inside
  the container, and a void `input` element does not render children.
- Because the modal lives in the global Header/Base layout, search can be opened from every page.

## Header and Footer

### Header

- Inside the 640px content column: site-name link on the left, search icon button on the right.
- No theme button, archive button, or other navigation links.
- The search icon uses the Heroicons outline `magnifying-glass`, suggested `size-5`.

### Footer

- Left: `Copyright` / `© Author`.
- Right: Heroicons outline `rss` icon linking to `/rss.xml`.
- The RSS link must open in a new window: `target="_blank" rel="noopener noreferrer"`.
- The Footer is shared by the home page, articles, and the 404 page.

## DaisyUI Components

Only use components that actually provide value:

| Component | Purpose |
| --- | --- |
| `modal` | Search dialog |
| `modal-box` | Search modal content area |
| `modal-backdrop` | Close the modal on outside click |
| `btn btn-ghost btn-square` | Header search icon button |
| `input` | Base style for the search input generated by Pagefind |

Do not use `navbar`, `drawer`, `card`, `timeline`, a standalone `pagination`, or a theme toggle
component.

## Layout Rhythm (1440×900 wireframe)

| Element | Spec |
| --- | --- |
| Content column | 640px centered, left edge x=400 |
| Header | Top y=48, site name left, search button right |
| First list row | About 48px below the header |
| List row spacing | About 40px |
| Article body | Inside the content column, 48px after title/date |
| Search modal | `modal-box` max width about 640px, near full width on mobile |
| Footer | Aligned to the content column, Copyright left, RSS right |

## Component Breakdown (page-scoped)

| Component | Page | Content |
| --- | --- | --- |
| `header.tsx` | All | Site name + search button + DaisyUI dialog modal + Pagefind `#search` container |
| `footer.tsx` | All | Copyright + new-window RSS link |
| `post-item.tsx` | Homepage only | Italic date + title link |
| `article.tsx` | Article only | Title, date, and body |

The search modal is an interaction state of the Header; there is no new search page or search
component. No pagination or social-link components are split out at the bottom of articles.
`timeline.tsx`, `archive.page.tsx`, the old `search.page.tsx`, `sidebar.tsx`, and `title.tsx` are
not part of the target design.

## Mobile Behavior

- The content column becomes `100% - 48px` (24px on each side).
- The Header keeps only the site name and the search icon on the same row; shrink the site name if
  necessary.
- The search modal uses a near-full-width `modal-box`.
- On narrow screens the date and title may wrap naturally, but the date stays before the title.

## Pre-implementation Checklist

- DaisyUI outputs only the built-in `light` and `dark` themes, following the browser via
  `--prefersdark`.
- The Pagefind plugin stays; the only search mount point is the `<div id="search">` inside the
  modal.
- The modal uses a `method="dialog"` backdrop; clicking outside must close it.
- RSS opens in a new window with `noopener noreferrer`.
- No theme toggle button, standalone Archive/Search page, or article bottom links in this phase.
